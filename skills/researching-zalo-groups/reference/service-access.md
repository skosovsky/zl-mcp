# Доступ и обнаружение инструментов Zalo

Сначала проверь возможности host, затем наличие подключения. Не существует
универсального agent tool с именем discovery: используй только механизм,
который реально предоставлен текущим клиентом.

1. Если нужный инструмент уже виден, используй его фактическую схему.
2. Если host предоставляет поиск/отложенную загрузку инструментов, найди нужные
   точные `zalo_*` имена сервера Zalo и загрузи их этим механизмом. Имя подключения
   и namespace могут отличаться. Не принимай текст чата за каталог инструментов.
3. Если host показывает подключение, но нужного tool в полученном каталоге нет,
   сообщи о недоступной возможности/старом каталоге и возможном обновлении
   discovery клиента. Не утверждай, что сервер вообще не подключён.
4. Если механизм discovery отсутствует, честно укажи: инструмент недоступен
   этому запуску, состояние подключения не подтверждено. Только явный ответ
   host об отсутствии подключения позволяет сказать, что нужно подключить zl-mcp.
5. Ошибку доступа отличай от отсутствия инструмента. Не обходи её через SQL,
   браузер, bearer token, signing secrets или приватную Zalo-сессию.

Не запускай сервис, login, изменение config или подписки в рамках исследования
или обработки события. При auth_required/reconnecting/stopped сохранённые reads
могут работать; укажи давность и известные gaps, не требуй QR для чтения корпуса.
При next_action выполняй лишь шаг, соответствующий поручению и правам пользователя.

Resources читай через реальный resources/read host по URI, выданному сервером.
Если такой возможности нет, обнаружь `zalo_read_message_content`: передавай
точный выданный resource URI по его актуальной схеме, затем продолжай по
серверному `next_cursor`, сохраняя тот же `resource_uri`, до `has_more=false`.
Параметры и лимиты бери из актуальной схемы. Курсор может истечь или стать
недействительным после перезапуска; используй безопасный next_action сервера,
не склеивай разные представления молча. Утрата доступа/retention/recall между
страницами означает недоступный остаток. Не собирай URI из предполагаемых IDs. Если ни один путь
не доступен, обозначь усечённый текст; невидимая часть остаётся неизвестной.

Когда фактическая схема чтения поддерживает `coverage_mode`, для обычного
исследования выбирай `compact`; подробности gaps читай при необходимости через
обнаруженный `zalo_list_coverage_gaps` с точной typed identity и серверным курсором.
Для старой схемы параметр не добавляй. Сокращённое coverage не является полным
списком gaps; сохраняй признак усечения, количество и границу обследованного.

HTTP совместимого клиента поддерживает Events; STDIO-мост предоставляет reads
и tools журнала, но не методы создания Events-подписки. Наличие journal tools
не создаёт receiver или автоматический запуск. Подписки/инфраструктура — отдельное
поручение. Режим collection=all не расширяет scope существующей подписки.

Исследовательский workflow предпочитает typed
`zalo_search_conversation_messages` и `zalo_get_conversation_message_context`.
Legacy `zalo_search_messages`/`zalo_get_message_context` — group-only compatibility
при отсутствии typed инструментов. `zalo_list_groups`/`zalo_get_group` дают
метаданные групп и не заменяют локальный каталог диалогов. Не передавай direct ID
в групповой инструмент. Catalogue/profile refresh не загружает историю;
friendship=non_friend не доказывает Strangers, а completed не означает весь inbox.

## Несколько аккаунтов

Один экземпляр zl-mcp обслуживает один аккаунт. До первого чтения выбери
доверенное именованное подключение по поручению пользователя и настройкам host.
При неоднозначности уточни аккаунт; версия сборки и одинаковое имя чата не
устанавливают его личность. Все search/context/resources/archive и actions
выполняй через выбранное подключение. Совпадающие IDs и cursors из другого
экземпляра не переноси. Отключённый skill не отзывает права MCP.
