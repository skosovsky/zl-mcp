# Результат обработки

Для пользователя начни с факта, подходящего под согласованное правило. Дай короткое подтверждение и источник: название диалога, если известно, тип и ID диалога/сообщения, автор (имя или ID) и время сообщения. Не выдумывай публичную ссылку Zalo. Полученный resource URI — локальный источник, не ссылка для внешнего адресата.

Укажи ограничения только когда они влияют на вывод: обрезка и недоступный полный текст, неполный контекст, известный разрыв сбора или старая дата сообщения. Если ресурс недоступен после retention, доступный префикс обозначь как префикс.

Синтетический пример для правила «сообщать об изменении времени встречи»:

> Встречу перенесли на 15:00. Автор написал «встречаемся в 15 вместо 14»; соседнее сообщение подтверждает ту же дату. Источник: группа g-1, сообщение m-42, автор user-7, 2026-10-02T09:00:00Z.

В доверенном результате обработки различай: не подходит под правило; подготовлено; доставлено; требуется повтор/уточнение. Не называй «доставлено» текст, который только подготовлен. Постоянную запись статуса выполняет предоставленный механизм клиента/harness.

Для Events v2 используй направление и признак первого локально известного входящего только из проверенного payload. `first_incoming=null` означает недостаточную историю; не называй такого собеседника новым. Первое локальное обращение не доказывает первое общение за всю историю Zalo.

Если явное поручение включает личный ответ, отдельно зафиксируй `request_id` и результат отправки. `sent` означает принятие Zalo, а не доставку или прочтение адресатом; `unknown` означает неоднозначный результат и требует проверки прежнего request_id, без автоматической повторной отправки. Недоступную цитату или запрет отправки укажи как причину отсутствия ответа. Не выдавай подготовленный текст за отправленный.
