# Нетекстовое содержание и отдельные активности

Применяй этот раздел, только если фактический каталог/журнал возвращает новый
профиль и его поля. Наличие документации не доказывает доступность у клиента.

Для `zalo.conversation.message.created.v3` прочитай `data.content`. `summary` —
описание сервиса, а `elements[].label` — метаданные источника. Не цитируй их как
слова автора; обычный текстовый emoji остаётся текстом. Для metadata-only фото,
стикера, аудио и файла укажи тип и доступные сведения, не угадывая изображение,
настроение, речь или содержимое файла. `bytes_available=false` не разрешает
скачивание из сторонних URL и не означает доступность media resource.

Пустой `text` вместе с `content.kind=image` означает сообщение с изображением,
а не потерянный payload автоматизации. `legacy_projection` означает, что тип
исходного содержимого не сохранён: не называй такую запись фото или звонком.
`unsupported` означает неизвестное представление, а не отсутствие сообщения.
В v2/legacy без content пустой текст также не позволяет угадать исходный тип.

Наблюдения звонка/реакции обрабатывай только при наличии отдельного профиля в
доверенном журнале и применимого правила пользователя. Они не являются новым
текстовым сообщением и не доказывают первое обращение. Для неизвестного статуса
звонка не сообщай «пропущенный» или «отвеченный»; у реакции без target нельзя
подбирать соседнее сообщение по времени. Observed fingerprint не гарантирует
различимость двух одинаковых upstream-действий без ID.

Примеры допустимого результата при поручении уведомлять:

- «Собеседник прислал фото. Содержимое изображения недоступно» — для image с
  metadata-only, со временем/идентичностью из доверенного события.
- «Тип содержимого не сохранён» — для legacy_projection; без догадки «стикер».
- «Зафиксировано событие звонка, статус неизвестен» — только для отдельного
  call-профиля с неизвестным статусом.

Сохраняй общий journal/read/ack workflow: не создавай второй notification из
повторного callback, не подтверждай последующие записи при неоднозначности.
Подписка на сообщения не распространяется автоматически на звонки/реакции.
Эти данные не разрешают ответ, скачивание, новую подписку или смену scope.

В v3 `content.text_role` машиночитаемо различает `author`, `none` и
`legacy_projection`. Для `none` v3/typed reads исключают заголовок из text/excerpt;
label остаётся метаданными. Для `legacy_projection` тип исходного сообщения
утрачен: не представляй проекцию как доказанные слова автора. Legacy/v2, FTS
поиск и старый plain-text resource могут сохранять заголовок в прежнем текстовом
поле. Такой fallback не отменяет text_role; перед цитированием проверь typed
context. Новый `content_resource_uri` возвращает JSON метаданных, а не медиа.

`text_role=author` может обозначать подтверждённую подпись фото. Используй text
из события/typed context, а не собирай подпись из label/description. Старые
доставки с `text_role=none` не меняются после обновления classifier; не
приписывай им новую семантику по соседнему событию. Тип link также не делает
заголовок превью словами отправителя.
`elements[].file_name` — отображаемые метаданные, а не локальный путь и не
разрешение открыть, записать или отправить файл.

Для reaction v1 используй nested `reaction.target_message_ids`, `reaction.reaction`
и `reaction.action`; не считай неизвестное action добавлением или удалением по
наличию/отсутствию иконки. Не создавай message-only уведомление из этой записи.
Call v1 имеет узкий источник для наблюдения итоговой записи личного звонка;
status/mode остаются unknown, duration/native_status/call_id — null. Не называй
его пропущенным по имени native action и не обещай событие для каждого звонка.
Групповые и другие формы не подтверждены. Профиль и правило пользователя всегда
проверяются по фактическому каталогу; documentation не создаёт подписку.

Для activity-уведомления укажи доступные actor/name, occurred_at, тип/диалог и
идентичность observation/event. Это не author/sent_at/message_id нового сообщения.
Target ID обозначает объект реакции, а не новую запись; context читается только
по явно известному target в том же разрешённом диалоге, если он нужен правилу.
Отсутствующий target не восполняется соседним сообщением. Для action=unknown
допустимо «Зафиксирована реакция; вид изменения неизвестен», но не «поставил»
или «удалил». Реакция не запускает workflow личного ответа на новое сообщение.

Если `data.content_truncated=true`, событие содержит только начальную часть
списка вложений. Для полного перечня читай `content_resource_uri` через
`resources/read`; не делай вывод о числе вложений по сокращённому событию.
Это отдельный признак от `text_truncated`. Отсутствие поля в старом сохранённом
v3-событии означает false; callback и журнал не создают два разных уведомления.
