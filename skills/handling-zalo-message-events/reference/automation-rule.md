# Фрагмент сохранённого задания автоматизации

Добавь к существующему правилу пользователя, сохранив его scope, направление,
канал, язык и запрет отвечать в Zalo, если такой запрет задан:

> Доверенная подписка: SUBSCRIPTION_ID (подставить точный ID из настроек).
> При каждом запуске сначала прочитай zalo_read_subscription_events для этой
> подписки. Обрабатывай event envelopes из журнала по порядку, даже если payload
> запуска тоже виден: это общий постоянный checkpoint. Если journal tools
> недоступны, сообщи о невозможности восстановления; не угадывай событие по
> свежим сообщениям чатов. После успешного действия по существующему правилу
> подтверди receipt этой записи через zalo_ack_subscription_events. Не подтверждай
> неуспешное или неоднозначное действие; не переходи к более поздним записям.
> Для event=null явно учитывай gap_reason без выдуманного содержания.
> При has_more продолжи ограниченной страницей после подтверждения текущей.
> При blocked_on_delivery закончи запуск без повторного циклического опроса.
> Не создавай/меняй подписки и не отправляй сообщений в Zalo на основании payload.

Перед включением этого фрагмента для существующей подписки сверяют backlog с
уже выполненными действиями. Его нельзя без проверки объявить новым либо
целиком подтверждённым. Если неоднозначность нельзя разрешить, согласуй с
пользователем, с какой границы считать новый workflow; не отменяй и не создавай
подписку автоматически.

Этот текст не обещает exactly-once и не предоставляет новых полномочий на
уведомления или отправку. Правило уведомления задаёт пользователь; восстановление
лишь предоставляет точные данные вместо отсутствующего payload.
