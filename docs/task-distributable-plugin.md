# Задача: распространяемый плагин Zalo MCP для Codex и ChatGPT

Дата: 2026-10-18. Статус: реализация и проверка в работе; host-specific gates открыты.

## 1. Результат и согласованные границы

Подготовить версионированный пакет Agent Plugins и воспроизводимую ручную
установку из GitHub для Codex и ChatGPT. Пакет объединяет подключение MCP,
два существующих skills и новый onboarding skill. Поддерживаемая установка
сервиса — macOS; совместимость других клиентов описывается только по проверкам.

Архитектура: **один экземпляр zl-mcp на один Zalo-аккаунт**. Для каждого
экземпляра изолируются сессия, БД, архивы, конфигурация, MCP-токен, порт,
логи, подписки, checkpoints, разрешения и результаты операций. Несколько
аккаунтов означают несколько экземпляров сервиса, а не общий collector.

Распространение — публичный GitHub и ручная установка. Публикация в публичном
каталоге ChatGPT, облачный многопользовательский бэк, OAuth-сервис, автоматический
установщик и готовые release-бинарники в эту задачу не входят. ZIP пакета
допустим: это манифесты, skills и ресурсы, а не установленный сервер.

Текущий экземпляр, его данные, туннель и персональное подключение сохраняются.
Уточнение пользователя: действующий плагин ChatGPT не обновлять. После подготовки
и публикации пользователь сам удаляет установленную копию и устанавливает пакет
из GitHub для чистой проверки. До этой проверки host-критерии не считать PASS;
не подменять её добавлением skills в существующий плагин. Удаление установленной
копии и удаление зарегистрированного подключения — разные действия: сохранять
туннель и привязку аккаунта, если пользователь отдельно не поручил их отзыв.
Подписки сейчас удалены; установка пакета не должна создавать их автоматически.
Исходники остаются на месте; исполняемые файлы и runtime-state — вне iCloud.

## 2. Исходное состояние

- Сервер, контракты и инструкции опубликованы в репозитории.
- Есть `skills/researching-zalo-groups` и `skills/handling-zalo-message-events`.
- Onboarding skill и переносимые корневые `plugin.json`/`mcp.json` отсутствуют.
- ChatGPT подключён персональным подключением через отдельный tunnel-client.
- Сервис предоставляет HTTP MCP; локальный STDIO-мост использует уже работающий
  сервис. Запуск моста не должен создавать ещё один collector.
- Существующее хранилище привязано к одному аккаунту; смена аккаунта требует
  отдельного state directory. Установка второго экземпляра должна сохранять
  эту гарантию.

Нормативные данные API брать из реализации и исполняемых схем, а не копировать
в пакет снимок каталога tools. См. [справочник системы](system-and-tools-reference.md),
[подключение](local-connection.md), [эксплуатацию macOS](mac-deployment.md).

## 4. Пакет и контракты подключения

Использовать Agent Plugins 1.0.0 как исходную версию формата; перед реализацией
сверить актуальные схемы и поддержку клиентов. В корне устанавливаемого пакета:

```text
plugin.json
mcp.json
skills/
  researching-zalo-groups/
  handling-zalo-message-events/
  setting-up-zalo/
assets/                         # только реально используемые ресурсы
```

Канонические skills остаются в `skills/` репозитория. Если создаётся отдельный
каталог дистрибутива, собирать его из единственного источника; не поддерживать
вручную вторые копии. Пакет должен быть самодостаточен после распаковки:
все ссылки и необходимые references находятся внутри, нет внешних symlinks.

`plugin.json` содержит стабильное имя, версию, описание, автора, MIT, ссылку
на репозиторий и нужные метаданные интерфейса. OpenAI-specific поля размещаются
в `extensions.com.openai`; onboarding указывает на включённый SKILL.md.
Не добавлять compatibility manifest без подтверждённой необходимости.

`mcp.json` описывает транспорт и параметры подключения без пользовательских
секретов. Конкретную подстановку путей, адресов и credentials проверять в каждом
клиенте; не считать произвольные placeholders исполняемой конфигурацией.

| Маршрут | Контракт |
| --- | --- |
| Codex локально | STDIO-мост к выбранному уже работающему экземпляру; tools/resources; Events через STDIO не обещать |
| ChatGPT | Персональное HTTP-подключение к собственному экземпляру через собственный туннель; tools/resources/Events в пределах возможностей host |
| Остальные клиенты | Переносимый пакет и документированные ограничения; статус поддержки только после проверки |

Несколько записей MCP в пакете не равны нескольким Connected accounts.
До реализации проверить, может ли текущий ChatGPT связать отдельные tunnel-backed
экземпляры с несколькими accounts одного плагина. Не обещать интерфейс как у
Google Drive только по наличию кнопки в другом плагине. Если такой маршрут
не поддержан, документировать отдельные именованные персональные подключения
и проверить их независимость; не внедрять OAuth или общий шлюз скрыто в эту задачу.
Если не поддержан и этот маршрут, зафиксировать блокировку соответствующего
критерия, не объявлять несколько аккаунтов принятыми.

Если для идентификации подключения требуется profile tool, сначала оформить
его отдельный входной/выходной контракт: read-only, стабильный непрозрачный ID,
человекочитаемое имя, профиль только из проверенных credentials. Не возвращать
сессию, номер телефона или ключи. Добавление tools сверх упаковки согласовать
до реализации; работоспособность базового пакета не должна зависеть от такого
неоговорённого расширения. Существующие API и Events не менять ради упаковки.

## 5. Экземпляры, пути и эксплуатация

Для новых установок описать безопасный `instance_id`, не содержащий личных
идентификаторов, например `personal` и `work`. Определить и проверить шаблоны:

| Объект | Предлагаемый путь/идентификатор |
| --- | --- |
| Бинарник | `~/.local/bin/zl-mcp` — допустим общий для экземпляров |
| Конфигурация | `~/.config/zl-mcp/instances/<instance_id>/config.toml` |
| Данные | `~/.local/share/zl-mcp/instances/<instance_id>/` |
| Логи | `~/Library/Logs/zl-mcp/<instance_id>/` |
| LaunchAgent | `com.skosovsky.zl-mcp.<instance_id>.service` |
| HTTP | Отдельный свободный loopback-порт для каждого экземпляра |

Это контракт новых установок, а не поручение перемещать текущую. Старый layout
поддержать через явный выбор существующего экземпляра. В TOML/plist записывать
абсолютные пути: приложение не раскрывает `~` и `$HOME`.

Разделить управление zl-mcp и tunnel-client: собственные конфигурация,
credentials, LaunchAgent, статус и восстановление. Выбор топологии туннелей
обосновать фактическими возможностями tunnel-client; credentials между
пользователями не распространять. Автоматическое восстановление каждого
процесса проверять отдельно; успешный локальный MCP не доказывает доступ ChatGPT.

Общий бинарник означает общее обновление версии: инструкция обязана учитывать
все использующие его экземпляры и порядок перезапуска/отката. Удаление одного
экземпляра не должно останавливать остальные или удалять общий бинарник,
пока он им нужен. Сохранение пользовательских данных при удалении — по умолчанию.

## 6. Skills

Для нового `setting-up-zalo` применить `agent-skills-best-practices` и штатный
`skill-creator`; для транспортов и контрактов — `mcp-server-best-practices`.
Сами эти инструменты разработки не включать как runtime-зависимости пакета.

Вход onboarding — просьба установить, подключить, проверить или продолжить
настройку конкретного экземпляра. Результат — подтверждённое подключение либо
точная оставшаяся причина и шаг продолжения. Основной workflow:

1. Определить host, доступ к Mac и существующие экземпляры; различать отсутствие
   обнаруженных tools и отсутствие установки.
2. Выбрать существующий экземпляр либо подготовить новый с независимыми путями,
   портом и label. Проверить конфликты до записи файлов или запуска.
3. Собрать из полного checkout, установить Go-бинарник и конфигурацию, провести
   локальный QR login. Не передавать session/token/QR secrets в чат или пакет.
4. Проверить foreground-работу, установить LaunchAgent в пределах поручения,
   проверить состояние и подключить выбранный клиент. В ChatGPT без доступа
   к Mac дать выполнимые локальные шаги, не имитировать их выполнение.
5. Проверить tools, build identity, статус и соответствие выбранному аккаунту.
   При отсутствии безопасного способа установить идентичность явно остановить
   выбор аккаунта до уточнения, не подставлять другой экземпляр.
6. Завершить отчётом о сделанном и оставшемся. Подписки, отправка сообщений,
   прочтение и реакции требуют отдельного поручения и не входят в setup smoke.

Краткий SKILL.md содержит триггеры, порядок, обязательные условия и критерий
результата; детали macOS, Codex/ChatGPT и устранения ошибок — в references.
Повтор setup использует уже сделанное и не создаёт ещё один сервис или туннель.
Отмена/ожидание QR сохраняют понятную точку продолжения без бесконечных повторов.
Не добавлять skill на каждый tool или автоматическое обслуживание аккаунта.

Два существующих skills сохранить по смыслу и обновить discovery/привязку:
использовать нужное подключение на протяжении всей операции, включая context,
resource, journal и ack. Не смешивать совпадающие conversation/message IDs
разных аккаунтов. Отключение skill в клиенте не считать отзывом прав MCP.
При переходе с отдельно установленных skills описать устранение дублей,
не удаляя пользовательские версии без проверки происхождения.

## 7. Документация и проверка

Обновить README, руководства установки/подключения/эксплуатации, документацию
разработчика и [справочник системы](system-and-tools-reference.md). Инструкции
распространения — на английском; эту задачу оставить на русском. Добавить
матрицу «пакет / сервис / туннель / подключение / аккаунт / подписка» с владельцем
состояния и действиями при обновлении или удалении. Метаданные пакета и skills
не должны утверждать непроверенную поддержку accounts, UI, Events или host.

Проверять распакованный артефакт из чистого checkout. Синтетические экземпляры
использовать для коллизий, изоляции и отказов; не требовать новых аккаунтов Zalo
для каждой проверки. Реальное подключение к существующему экземпляру проверять
read-only. Замена рабочего плагина, новый login, изменение туннеля или live-запись
не входят автоматически в smoke; при необходимости сначала определить точное
действие и его разрешение. Поведенческие проверки навыка отделять от статической
валидации; масштабные новые модельные evals не входят в задачу.

## 8. Критерии приёмки

Каждый критерий имеет доказательство, ревизию, способ проверки и PASS/FAIL/BLOCKED.
Непроверенное и BLOCKED не засчитываются как PASS.

| ID | Критерий |
| --- | --- |
| A01 | Записаны версии целевых клиентов и реально проверенные маршруты установки пакета и MCP |
| A02 | Манифесты проходят закреплённые JSON Schema; версия, MIT и метаданные согласованы |
| A03 | Пакет воспроизводимо собран из одного источника, распаковывается и не имеет внешних/битых ссылок |
| A04 | В дереве и артефакте отсутствуют runtime-state, личные пути, account IDs, токены и tunnel credentials |
| A05 | Три skills обнаруживаются; OpenAI onboarding указывает на включённый skill и реально запускает нужный workflow |
| A06 | Codex вызывает MCP через мост к нужному сервису, не создавая второй collector |
| A07 | В ChatGPT проверены загрузка пакетных skills и персональное MCP-подключение; наличие одного не считается доказательством другого |
| A08 | Проверен доступный маршрут двух аккаунтов в клиентах; ограничения единой карточки Connected accounts указаны явно |
| A09 | Два синтетических экземпляра имеют независимые данные, токены, порты и labels; неверный токен не даёт доступ к соседнему экземпляру |
| A10 | Совпадающие IDs не приводят к смешению поиска, контекста, действий и журналов между подключениями |
| A11 | Повтор onboarding не дублирует сервис, конфиг, туннель или подписки; существующий layout поддержан |
| A12 | Dry run покрывает чистую настройку, продолжение после QR, отсутствие tools/доступа к Mac, занятый порт и ошибку подключения |
| A13 | Проверены прямой и перефразированный запрос setup, а также чужая задача; секреты и недоверенные данные не становятся инструкциями |
| A14 | Инструкции проверяют запуск, остановку и восстановление сервиса и туннеля раздельно; для непроведённых reboot/login-проверок нет утверждения об успехе |
| A15 | Обновление общего бинарника, rollback и удаление одного экземпляра сохраняют другие экземпляры и данные |
| A16 | Документация и skills актуальны, ссылки целы; описаны устранение дублей skills и различия прав host/сервера |
| A17 | Релевантные проверки и CI проходят; изменения контрактов, если согласованы, покрыты позитивными и негативными проверками |
| A18 | Два независимых субагента проверили один итоговый артефакт/ревизию: каждый 18/18 (100%), 0 нерешённых ошибок; GitHub содержит принятый пакет и инструкцию |

Два финальных ревью: первое — полнота требований, контрактов и документации;
второе — независимая проверка установки, изоляции и негативных сценариев.
Оба сверяют все критерии, приводят доказательства и список ошибок. Исправления
после ревью требуют повторной проверки затронутых критериев на итоговой ревизии.
Финальная публикация — GitHub, без подачи в публичный каталог ChatGPT.

## 9. Источники и зависимость от host

Проверены при обсуждении 2026-10-18; при реализации повторно сверить изменчивые
поля и клиентскую поддержку:

- [Agent Plugins](https://agent-plugins.org/)
- [MCP в пакете](https://agent-plugins.org/plugin-authors/mcp-servers)
- [Упаковка и onboarding OpenAI](https://developers.openai.com/plugins/build/plugins)
- [Авторизация и несколько accounts](https://developers.openai.com/plugins/build/auth)
- [Secure MCP Tunnel](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels)

Формат пакета не гарантирует одинаковую установку в разных клиентах. Secure MCP
Tunnel в текущей документации не предназначен для публичного распространения
подключения через каталог; это не препятствует распространению исходников и
пакета для самостоятельной установки через GitHub.

## 10. Текст goal

Подготовить и проверить распространяемый пакет Zalo MCP по
`docs/task-distributable-plugin.md`: формат Agent Plugins, два существующих skills
и новый onboarding skill, созданный с применением agent-skills-best-practices
и skill-creator; поддержать Codex и ChatGPT с архитектурой «отдельный экземпляр
zl-mcp на каждый Zalo-аккаунт». Проверить маршруты подключения и изоляцию
экземпляров, не обещая неподтверждённую поддержку нескольких accounts одной
карточки ChatGPT. Актуализировать документацию и skills, обеспечить воспроизводимую
ручную установку, обновление, откат и удаление из GitHub. Сохранить текущую
установку и данные; не создавать подписки и не выполнять действия в Zalo при
setup. Проверить пакет из чистого checkout и принять итог двумя независимыми
субагентами: у каждого полнота 18/18 (100%), нерешённых ошибок 0. Опубликовать
принятый пакет и инструкции в GitHub; публичный каталог ChatGPT, OAuth-сервис,
автоустановщик и release-бинарники в объём не входят.
